# 급등락 종목 이슈 요약 에이전트 구현 실습

2025 미래에셋증권 AI 페스티벌(AI Service 부문)에 제안한 **"애프터브리핑"** 서비스 중, 제가 맡았던 **이슈 요약 에이전트**의 요약·평가·피드백 단계를 직접 구현해 본 개인 프로젝트입니다.
대회에서는 제안서 단계까지만 진행했기 때문에, 설계가 실제로 동작하는지 확인하고 싶었습니다.

- 기간: 2026.11.09
- 사용: Python, Gemini API(`google-genai`), Kiwi 형태소 분석기(`kiwipiepy`)
- 데이터: 2026년 11월 9일 급등락 종목 뉴스 5건, 기사마다 제가 직접 쓴 기준 요약 5개

## 무엇을 구현했나

제안서(14쪽)의 이슈 요약 노드와 피드백 노드를 구현했습니다. 중복 기사 처리, 감성 분석, 이슈 유무 판단 노드는 이번 범위에서 제외했습니다.

```
기사 ──▶ 요약 노드 ──▶ 평가 노드 ──┬─ 통과 ──────────────────────────▶ Approved
        (Gemini,      (ROUGE-1,    │
         400자 이내)   ROUGE-L)     └─ 미달 ─▶ HITL 분기 (사람이 선택)
                                               ├─ 재시도 ─▶ 2차 요약 ─▶ 평가 ─┬─ 통과 ▶ Approved
                                               │                              └─ 미달 ▶ Rejected
                                               └─ 중단 ─────────────────────────────▶ Human_Rejected
                         모든 시도는 피드백 DB(JSON)에 기록
```

| 파일 | 역할 |
|---|---|
| `summarize.py` | 요약 노드. 시스템 프롬프트로 출력 형식을 고정하고, 요청 제한(429) 시 재시도 |
| `rouge_eval.py` | 평가 노드. 한국어 ROUGE-1·ROUGE-L을 라이브러리 없이 직접 구현 (어절·형태소 두 방식) |
| `feedback_loop.py` | 피드백 루프 v1. 미달 시 HITL 분기, 재시도 |
| `feedback_loop_v2.py` | 피드백 루프 v2. 실패 원인을 진단해 재시도 지시를 다르게 줌 |
| `compare.py` | v1·v2 결과 비교 |
| `data/news_public.json` | 기사 메타데이터와 기준 요약 (기사 본문은 저작권 때문에 제외) |
| `summaries.json`, `feedback_db.json`, `feedback_db_v2.json` | 1차 요약, v1·v2 실행 기록 |

## 실행 방법

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # GEMINI_API_KEY 입력
# news.json 준비: data/news_public.json의 링크에서 기사 본문을 body에 넣는다
python summarize.py             # 1차 요약
python rouge_eval.py            # 평가
python feedback_loop.py         # v1 피드백 루프
python feedback_loop_v2.py      # v2 피드백 루프
python compare.py               # 비교
```

## 결과와 알게 된 것

### 1. 한국어 ROUGE는 토큰화에 따라 점수가 크게 달라진다

조사 때문에 '박셀바이오는'과 '박셀바이오가'가 다른 단어로 처리됩니다. 같은 요약도 어절 기준 ROUGE-1은 0.30~0.45, 형태소 기준은 0.46~0.67이었습니다. 평가는 형태소 기준으로 했습니다.

### 2. 제안서 기준값을 그대로 쓰면 정확한 요약도 떨어진다

제안서의 기준값(ROUGE-1 0.55, ROUGE-L 0.50)을 적용하자 처음에는 5개가 모두 Rejected였습니다. 직접 읽어보면 내용은 정확했는데, ROUGE-L이 0.34~0.52에 머물렀습니다. 영어 데이터에서 나온 기준값이라 판단해 ROUGE-L 기준을 0.40으로 낮췄습니다. 다만 기사 5개로 정한 값이라 확정된 기준은 아닙니다.

### 3. ROUGE는 사실 여부를 확인하지 못한다

한 1차 요약은 장중 시세(오후 2시 17분 기준)를 "거래를 마감했다"고 잘못 썼는데도 ROUGE-1이 0.545로 기준에 거의 닿았습니다. 단어 겹침만 보는 지표라 사실 오류를 걸러내지 못하므로, 사람이 검토하는 HITL 단계가 필요하다는 것을 확인했습니다.

### 4. 실패 원인을 구분하지 않는 재시도는 효과가 없다 (v1 → v2)

v1은 정밀도가 재현율보다 조금만 낮아도 "너무 길다, 줄여라"를 지시했고, 재시도 temperature를 0.7로 올렸습니다. 세 기사 모두 점수가 오르지 않았고, 모델은 글자 수 지시도 잘 지키지 않았습니다(251자 지시 → 316자).

v2에서는 세 가지를 바꿨습니다.

| v1의 문제 | v2의 대응 |
|---|---|
| 정밀도·재현율 0.01 차이로도 "너무 길다"고 판단 | 어느 지표가 떨어졌는지 먼저 확인. 정밀도·재현율은 0.05 이상 차이 날 때만 사용 |
| 글자 수 지시를 지키지 않음 | 코드로 길이를 재서 기준의 1.2배를 넘으면 다시 요청 |
| temperature 0.7이 무작위성만 늘림 | 재시도도 0.2로 유지, 지시 내용만 변경 |

| 종목 | v1 재시도 (R1 / RL) | v2 재시도 (R1 / RL) | v2 진단 |
|---|---|---|---|
| 아시아나IDT | 0.484 / 0.357 | 0.511 / 0.397 | 군더더기 |
| 한싹 외 보안주 | 0.559 / 0.338 | 0.488 / 0.315 | 순서 |
| 알테오젠 | 0.441 / 0.409 | 0.504 / 0.446 | 군더더기 |

- **"군더더기" 진단은 효과가 있었습니다.** 두 기사 모두 두 지표가 올랐고, 알테오젠은 ROUGE-L 기준을 넘었습니다.
- **"순서" 진단은 역효과였습니다.** 문장 구조를 바꾸자 모델이 다른 표현을 써서, 기준 요약과 겹치는 단어가 줄었습니다. 기준 요약 하나와 비교하는 ROUGE는 같은 내용의 다른 표현에도 벌점을 줍니다.
- Approved 수는 v1과 v2 모두 5개 중 2개로 같았습니다.

## 한계와 다음 개선점

- **표본이 작습니다.** 기사 5개를 한 번씩 돌린 결과입니다. temperature 0.2에서도 같은 기사의 점수가 실행마다 달라져, 차이가 우연인지 판단하려면 기사 수와 반복 횟수를 늘려야 합니다.
- **1차와 재시도의 모델이 다릅니다.** 1차 요약은 `gemini-3.5-flash`, 재시도는 무료 할당량 소진으로 `gemini-3.5-flash-lite`를 썼습니다. 그래서 1차와 재시도 점수는 직접 비교할 수 없습니다. v1과 v2는 같은 모델로 비교했습니다.
- **재시도 결과가 1차보다 나쁠 수 있습니다.** 다음에는 1차와 2차 중 점수가 높은 요약을 남기도록 바꿀 계획입니다.
- **평가 지표를 보완해야 합니다.** 사실 오류를 잡으려면 기사 속 수치(등락률, 주가)가 요약에 정확히 들어갔는지 코드로 확인하는 규칙이나, 기준 요약을 여러 개 두는 방법을 검토할 수 있습니다.

## 역할과 AI 도구 활용

- 원래 제안서는 3인 팀이 함께 작성했고, 저는 이슈 요약 에이전트의 처리 흐름을 제안했습니다. ROUGE 기준값을 논문(See et al., 2017)에서 찾아온 것은 다른 팀원입니다.
- 이 구현 실습에서는 **Claude(AI)의 도움**을 받았습니다. 코드와 설명은 Claude가 작성했고, 저는 기준 요약 작성, 직접 실행과 오류 확인, HITL 분기에서의 재시도·중단 판단, 결과 검토와 개선 진행 여부 결정을 했습니다.
